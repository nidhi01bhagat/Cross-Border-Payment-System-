## 💡 Pro Tips

**1. Bookmark GIT_QUICK_REFERENCE.md**
- Print it
- Keep it at your desk
- Reference every day

**2. Commit frequently**
- Every 15-30 minutes
- Smaller commits = easier to debug
- Easier to undo if needed

**3. Write good commit messages**
- "Fix webhook timeout" ✅
- "asdf" ❌
- Helps team understand what changed

**4. Pull before pushing**
- `git pull origin main` first
- Prevents merge conflicts
- Takes 2 seconds

**5. Use branches for everything**
- Never push directly to main
- One branch = one feature
- Easy to review and merge

## 🚨 Emergency Commands

If something goes wrong:

```bash
# See what happened
git status
git log --oneline
git diff

# Undo uncommitted changes
git checkout .

# Undo last commit (keep changes)
git reset HEAD~1

# See all branches
git branch -a

# Start fresh (nuclear option)
git reset --hard origin/main
```

## 📞 Common Questions

**Q: Where do I clone to?**
A: Anywhere you like. This guide uses `c:\Users\NEHA\CrossPay\`

**Q: Do I need to read all 5 documents?**
A: No. Read GIT_QUICK_START.md (5 min), then GIT_QUICK_REFERENCE.md, then ask if confused.

**Q: What if my teammate and I edit same file?**
A: Normal! Git merges automatically. If it can't, you edit manually. See GITHUB_TEAM_GUIDE.md for details.

**Q: Can I delete a branch?**
A: Yes, after merging it to main: `git branch -d feature/name`

**Q: What if I push broken code?**
A: Create new commit that fixes it. Or use `git revert` to undo. Judges won't see GitHub history anyway!

**Q: Can we test locally without GitHub?**
A: Yes, Git is local-first. Push to GitHub only when ready.
